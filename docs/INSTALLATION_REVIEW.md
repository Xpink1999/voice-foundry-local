# 下载、安装与首次启动检查

检查日期：2026-10-23。

## 检查方法

从 GitHub 下载 `7405541` 的源码 ZIP，在带中文和空格的独立目录解压，再应用本次修复。初始目录不含 `.venv`、`runtime`、`models`、`vendor`、`data` 或 Git 历史。Python、依赖、源码和模型重新获取；没有复制生产安装的虚拟环境、数据库、参考录音或音色。

这是同一台 Windows 11 电脑上的隔离安装检查，不等于全新 Windows 虚拟机验收。Git、uv、NVIDIA 驱动和系统运行库属于明确的系统前置依赖。核心安装不要求 Git、CUDA 或 FFmpeg。

## 发现与修复

| 环节 | 问题 | 修复 |
|---|---|---|
| 下载 | 没有说明 ZIP 应解压到哪一层、能否在压缩包内运行 | 四语说明补充 Code → Download ZIP、全部解压、目录识别和 Git 克隆步骤 |
| 首次入口 | 未安装就启动只会得到找不到 Python 的错误 | 增加 install-voice.cmd；启动器缺环境时给出安装命令和非零退出码 |
| Python | uv 的版本链接权限失败会使已经下载的解释器也无法使用 | 校验项目内完整解释器路径、版本和基础模块，通过后直接建立专用环境；不回退系统 Python |
| 环境隔离 | 未屏蔽外部 Python 路径，临时目录也可能受系统权限影响 | 安装时清除 Python 和服务目标覆盖项，使用本目录 uv 状态、缓存与临时目录，退出后恢复进程环境 |
| 安装选择 | SkipModels 仍下载数 GB CUDA 包，不适合只看界面 | 增加 CoreOnly；明确它与完整安装、仅跳过权重的区别 |
| CUDA 依赖 | 大文件下载发生重试，下载来源不够直观 | 固定官方 Windows x64 / Python 3.11 CUDA wheel 地址及 SHA-256，延长下载超时 |
| 目录配置 | 下载器固定写默认模型目录，未跟随配置 | TTS、参考分析和音频处理下载器读取各自的集中路径配置 |
| 中断重试 | 完整但无效的 partial 文件可能反复请求越界 Range | 清除无效完整临时文件后重新下载，保留仍可续传的部分文件 |
| 启动目标 | 同端口旧服务可能被误当成本次安装，停止命令也可能指向它 | 本地调用核对安装标识；兼容旧服务时核对数据目录；显式远程 URL 保留原行为 |
| 加载失败 | 模型尚未成功加载就记录为 active，后续重试可能跳过加载 | 成功加载后才记录状态；失败时清理部分状态；普通与长文共用加载逻辑 |
| 首次试听 | 筛选复选框被通用输入框的最小宽度撑大，标签挤出 | 单独约束复选框尺寸，核对标签和首次音频波形显示 |
| 未装模型 | 首次生成只暴露底层导入错误 | 显示安装命令；清理未加载的模型时不再强制导入未安装的 Torch |
| 安装结束 | 启动失败未检查退出码，缺少整体检查结果 | 检查每个步骤退出码，输出安装日志和环境/模型检查报告 |
| 外部工具 | FFmpeg 的影响和 Windows DLL 依赖未说明完整 | 列出录音解码、编码、裁剪、响度和分离要求，补充 Visual C++ x64 运行库指引 |
