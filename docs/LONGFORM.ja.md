# 長文の音声化

「制作 → 長文の音声化」を開きます。既存作品が先に表示され、新規作品の読み込み欄は展開できます。声の説明とクローンモードは任意の設定です。章の審査と書き出しは作品内で行います。画面の案内は[WebUI 操作](WEBUI.ja.md)を参照してください。

## 取り込みと分割

長文の音声化画面で TXT または Markdown を取り込み、音色とプロジェクトを選びます。章と区間を確認してから、全巻または選択した章を生成します。ブラウザーを閉じても処理は続きます。止めるときは一時停止を使ってください。サービスの再起動後も、同じ作品を開いて再開できます。完成した区間は保持されます。

見出しや改行は必須ではありません。

- 独立した中国語の章・節などの見出し、Chapter の数字・ローマ数字、序章や終章、Markdown 見出しを認識します。
- 見出しがなければ、段落と約 30,000 文字の区切りで自動的に章を作ります。これは管理用の単位で、原書の目次ではありません。
- 段落がなくても句読点と長さで分割します。標準の音声区間は最大 160 文字です。正規化した UTF-8 本文でのバイト位置と内容のハッシュを記録します。
- 規則による検出なので、特殊な見出し、目次、ページヘッダーを確認してください。誤った章や区間は管理画面で除外・復元し、再審査できます。

文字コードは自動、UTF-8、UTF-16（BOM の有無と明示的なバイト順を含む）、GB2312、GBK、GB18030 を選べます。自動では BOM を確認し、全文を UTF-8 として検証してから GB18030 を試します。GB2312 ファイルでも、実際のデコーダー名として GB18030 と表示される場合があります。変換エラーを代替文字で隠さず、原本を残すので、別の文字コードでやり直せます。

## 保存と上限

長文は通常の 60,000 文字入力欄や 200 件の一括 API とは別の処理です。全巻分の通常タスクを一度に大量作成しません。SQLite が作品、章、区間、生成試行を索引化し、画面はページ単位で読み込みます。改行のない長い行も一定量ずつ解析し、区間の索引は 1,000 件ごとに保存します。

原本は `data/longform/<作品 UUID>/source.original` に保存します。改行を統一した UTF-8 本文は別ファイルです。両方の SHA-256 を保持し、区間位置は正規化後の本文を指します。元の GB2312 や UTF-16 のバイト位置とは異なります。

取り込み時に、作品の音色の版、既定の参照と文字起こしの版、モデル、パラメーター、基本シード、分割と無音設定を固定します。区間を再生成するときは、その区間専用の参照と演技設定を保存でき、作品の既定値は変わりません。標準の取り込み上限は原本の **2 GiB** で、設定可能です。モデルへの入力は小さな区間のままです。実際の制作量はディスク、実行時間、モデルの能力に制約されます。

## 再開・再試行・別テイク

通常の TTS、音声処理とモデル・計算ロックを共有します。区間ごとに状態、試行、本文と音声のハッシュ、モデル、参照設定のハッシュ、実際のシードを保存します。作品・章・状態の索引から次の区間を選び、成功した区間は通常キューへ再投入しません。

一時停止や再起動では未完了の区間が待機状態に戻り、成功済みの記録と音声は残ります。失敗すると作品を一時停止します。失敗区間を再試行するか、失敗を飛ばして残りを続けられます。モデルや参照のハッシュが変わった場合は、条件の異なる再開を拒否します。

### 参照を調整して一つの区間だけ再生成する

先に作品を一時停止し、実行中の書き出しを完了または中止してください。成功または失敗した区間の参照調整・再生成を開き、本文と現在の音声を確認します。人物の場面別参照や参照クリップ集から選び、参照の音声と文字起こしを確認してから、制御可能なクローンの演技指示と任意のシードを設定できます。Hi-Fi は正確な文字起こしを必要とし、参照の話し方に従うため、追加のスタイル指示は使いません。

既定では、その区間に固定された参照と設定を引き継ぎます。人物の既定参照を後から変更しても自動では反映しません。取り込み時の参照と設定に戻す項目を選ぶと、作品の既定値に戻してから今回の変更を指定できます。一つの区間の再生成は対象だけを処理し、章や全巻の残りを続けて生成しません。他の区間と作品の既定値は保持します。作品全体の音色やモデルを変える場合は、引き続き別作品として取り込んでください。

過去の音声と試行記録は残ります。版の履歴で成功済みのテイクを聴き比べ、以前の版を採用できます。再生成でも以前の版の採用でも、その章は審査待ちに戻るため、正式な書き出し前に再度試聴・承認してください。失敗区間は従来の設定で再試行することもできます。モデルや固定参照ファイルが一致しない場合は、別条件へ自動で置き換えず生成を拒否します。

通常の試聴・審査画面の候補にも参照調整・再生成があります。新しい審査待ち候補を作り、元の候補と承認状態は変えません。長文の章審査、進捗、書き出しは作品内で管理します。

固定参照は変動を抑えますが、全巻で声質や韻律が完全に一致する保証はありません。停止が反映されるタイミングはモデルのストリーミングや返却の区切りに依存します。

## 章ごとの試聴と審査

章内の連続再生と区間単位の再生に対応します。プレーヤーは一度に一つの区間を読み込みます。再生が終わっても試聴確認や承認は行いません。

承認には、章内の有効な全区間の成功と、利用者による試聴済みの確認が必要です。再生成、除外、復元で変わった章は審査待ちに戻ります。他の章の承認は保持します。履歴は `lf_reviews`、旧音声は試行別のフォルダーに残ります。

## 書き出し

作品の書き出し画面で、現在の章、全巻を章別ファイル、全巻を一つのファイルから選びます。WAV、FLAC、MP3、OGG はモデルの元のサンプルレートを使い、追加のエンコードはローカルの FFmpeg で行います。

正式な書き出しには、選択した有効章の完成と現行音声版の承認が必要です。未審査の内容は明示的に下書きを選択してください。音声と ZIP の名前に DRAFT、マニフェストに `draft=true` を記録します。通常の生成結果の承認状態は変更しません。

音声と ZIP64 を一定量ずつ書き出します。RIFF の容量を超える見込みの WAV は RF64 を使います。古いプレーヤーで読めない場合は章別または FLAC を選んでください。全巻の結合では中間の章別 WAV も保持するため、追加容量が必要です。全巻の PCM をメモリーに結合しません。

設定スナップショット、原本ハッシュ、本文と採用テイクのパラメーター・音声ハッシュを含む `segments.jsonl`、`chapters.jsonl`、区間単位の字幕、`generation-profiles.jsonl` を同梱します。後者は書き出しで使った区間別の上書き設定を設定ハッシュごとに記録します。各 take の `generation_profile_id` から参照でき、上書きのない区間は作品のスナップショットを使います。章別 SRT はゼロから、`book.srt` は全巻の時間軸です。単語単位のアラインメントではありません。

書き出し中はその作品の生成変更を固定します。他の作品と通常 TTS は利用できます。中止・失敗・中断時も書き込み済みファイルを保持し、新しい書き出しで再試行できます。区間の原音は上書きしません。ダウンロードはストリーミングで、CLI は ZIP の SHA-256 を検証します。

## クローン方式

- `clone_mode=reference`：参照音色と、任意の括弧付きスタイル指示を使用します。速度、感情、演技の指定は近似的な誘導です。
- `clone_mode=hifi`：同じクリップを `reference_wav_path` と `prompt_wav_path` に指定し、正確な `prompt_text` を渡します。追加スタイルを重ねず、参照の話し方に従います。

ワークベンチで参照の全文文字起こしを編集・保存できます。入力するのは参照録音の内容で、新しい台詞ではありません。通常、一括、長文の各画面で方式を選べます。未確認の自動文字起こしは下書きとして記録します。Hi-Fi という名称は類似性や試聴承認を保証しません。

## 削除と復元

管理とごみ箱では、プロジェクト、音色と版、参照と録音、タスク、試聴結果、書き出し、処理、比較、長文作品・章・区間・書き出しを扱います。単件・一括の削除、関連項目の確認、選択や削除バッチ単位の復元が可能です。

削除は日常の一覧から移す操作です。モデル、本文、音声、追跡記録は物理削除せず、容量も空きません。実行中のタスクは先に停止します。音色に紐づく参照は解除するか、音色と同じバッチで削除します。現行の音色版だけを削除することはできません。保護された項目が一つでもあれば、バッチ全体を拒否します。

作品全体を削除しても、膨大な区間を個別のごみ箱項目には展開しません。章の削除は同じバッチで有効区間を除外します。章を復元しても、以前に個別削除した区間は戻しません。内容が変わった章は再審査が必要です。

通常の試聴・審査画面では、複数結果の審査と書き出しや、確認画面から承認後の書き出し準備ができます。詳細設定は書き出しセンターにあります。試聴確認なしでは承認できず、未審査の結果が混ざった選択は正式に書き出せません。

## CLI・MCP・API

例は任意のグローバル CLI 登録後に使用します。ID の文字列をサービスが返した ID に置き換え、必要なコマンドを実行してください。

~~~powershell
$voiceId = "VOICE_ID"
$bookId = "BOOK_ID"
$exportId = "EXPORT_ID"
voice import-book .\book.txt --encoding auto --voice-id $voiceId
voice book $bookId --chapters
voice book-resume $bookId
voice book-pause $bookId
voice book-retry-failed $bookId
voice book-segments $bookId 1 --limit 25
voice book-generation $bookId 1
voice book-attempts $bookId 1
voice book-regenerate $bookId 1 --reference-id REFERENCE_ID --start
voice book-use-attempt $bookId 1 1
voice book-export $bookId --mode chapters --draft
voice book-export-status $exportId
voice book-download $exportId --dest .\output
~~~

`book-generation` は固定済み設定、`book-attempts` は過去の生成履歴を表示します。`book-regenerate --start` は指定区間だけ生成し、`--start` を省略すると設定を更新して再開待ちにします。`book-use-attempt` は成功した旧版を採用します。いずれも章を再審査してください。通常候補は `voice regenerate-result RESULT_ID --reference-id REFERENCE_ID` で審査待ちの新候補を作ります。MCP にも参照再生成、履歴取得、版の採用があります。クリップ管理は `voice references`、`voice update-reference REFERENCE_ID metadata.json`、`voice attach-references VOICE_ID --ids REFERENCE_ID` を使います。

`voice delete-assets` は `--apply` がなければ変更のプレビューです。削除バッチ ID を `voice restore-asset-batch` に渡すと一括復元できます。

REST の接頭辞は `/api/v1/longform` と `/api/v1/assets` です。完全な仕様は起動中の `/docs` で確認できます。区間再生成、過去の音声、版の採用のフィールドは [API ガイド](API.md#按参考重做)（中国語）にあります。MCP は取り込み、ページ取得、再開、書き出し、素材管理を提供しますが、試聴を代行して承認するツールはありません。更新後は MCP に再接続してください。モデルの再インストールは不要です。

## 設定と検証範囲

`config/platform.json` の `longform` に `max_source_bytes`、`segment_chars`、`fallback_chapter_chars`、`import_batch_segments`、`pause_ms`、`block_frames` をまとめています。変更は新しく取り込む作品に反映します。

オンライン DB バックアップには長文の索引とごみ箱のメタデータが含まれます。完全復元には `data/longform` と他の音声フォルダーも必要です。原本、正規化本文、生成試行、書き出しは保持し、復元不能な容量整理は実装していません。大容量取り込みテストと全巻の音声生成・人による試聴評価は別です。[検証範囲](TESTING.md)は中国語です。
