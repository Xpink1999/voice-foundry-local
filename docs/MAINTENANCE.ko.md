# 유지 관리·복구·업데이트

‘관리 → 모델 및 설정’을 엽니다. 지원 언어와 모델 버전, 저장 경로와 실행 환경은 필요할 때 펼쳐 보세요. 실행 설정을 바꾼 뒤에는 저장해야 합니다. 표시 언어와 테마는 오른쪽 위에서 따로 고릅니다. [WebUI 사용법](WEBUI.ko.md)에 화면이 있습니다.

## 일상적인 실행

설치 폴더에서 `start-voice.cmd`, `stop-voice.cmd`, `check-health.cmd`를 사용합니다. 선택 사항인 전역 CLI 등록 후에는 `voice start`, `voice stop`, `voice health`도 사용할 수 있습니다. 시작 파일은 WebUI도 엽니다. Windows 서비스나 시작 프로그램은 등록하지 않습니다.

모델은 생성할 때만 별도 추론 프로세스에 로드합니다. 기본적으로 30초 동안 유휴 상태이면 해당 프로세스를 종료해 가중치, PyTorch 런타임, CUDA 컨텍스트를 해제합니다. 대기 시간은 설정에서 바꿀 수 있습니다. `voice unload`는 중지된 서비스를 시작하지 않고 유휴 추론 프로세스를 해제합니다. 브라우저를 닫으면 미리 듣기는 멈추지만 백그라운드 작업은 계속됩니다. 도구를 종료하려면 `stop-voice.cmd` 또는 `voice stop`을 실행하세요. 서비스가 종료될 때까지 기다립니다. 저장한 오디오는 보존되며 미완료 장문은 나중에 이어 작업할 수 있습니다. 시작과 라이브러리 탐색에서는 모델을 로드하지 않습니다. 경량 서비스가 사용하는 메모리는 중지 후 회수됩니다.

설정은 `config/platform.json`에 있습니다. 저장 경로를 바꿀 때는 서비스를 멈추고 백업한 뒤 에셋·DB를 복사하고 경로를 갱신하세요. 모델 폴더만 옮기고 이전 설정을 남기지 마세요.

로그는 `runtime/logs/`에 있습니다. `platform.log`는 순환 예외 로그이고 `server.log`는 시작 및 상위 모델 출력을 담습니다.

## 백업

설치 폴더에서 실행합니다.

~~~powershell
bin\voice.cmd backup
~~~

SQLite 온라인 백업으로 일관된 `platform.sqlite3`와 `platform.json`을 `data/backups/<UUID>`에 저장합니다. **오디오 파일은 백업하지 않습니다.**

전체 복구를 위해 데이터 폴더 전체도 보관하세요. `references`, `recordings`, `reference-comparisons`, `audio-processing`, `originals`, `exports`, `longform`을 포함합니다. 장문 데이터에는 원문·정규화 본문, 구간별 생성 시도, 백그라운드 내보내기가 있습니다. 모델의 `provenance.json`, 소스 커밋, 의존성 잠금 파일도 보관합니다. 큰 가중치는 고정 리비전으로 다시 받을 수 있습니다.

DB와 파일 시점을 맞추려면 전체 데이터 복사 중 서비스를 멈추세요. 교체 전 현재 상태의 복구용 사본을 남기세요.

전역 등록 전 사용자 PATH와 Codex 설정은 `data/backups/global-<시각>`에 백업됩니다. 개인 설정이 포함될 수 있으므로 로컬에만 보관하고 공유 로그에 넣지 마세요.

## 복구

1. 플랫폼을 멈추고 현재 데이터를 별도로 보관합니다.
2. 백업한 SQLite, 일치하는 설정, 오디오·본문 폴더를 설정된 위치에 둡니다.
3. 모델·참조·원본 해시를 확인한 뒤 서비스를 시작하고 상태와 작업을 확인합니다.

중단된 일반 생성은 실패로 표시되며 이전 결과를 덮어쓰지 않고 재시도할 수 있습니다. 장문의 미완료 구간은 대기로 돌아가고 작품은 명시적 재개를 기다립니다. 가져오기 중단은 보존한 원본으로 다시 분석하고 내보내기 중단은 새 작업을 제출합니다. 원본 해시가 바뀌면 재사용을 거부합니다.

개별 실패를 해결하려고 알 수 없는 partial 파일이나 DB를 지우거나 목소리 라이브러리 전체를 다시 만들지 마세요.

## 업데이트와 스키마

먼저 백업하세요. 새 코드나 모델은 격리한 환경·설정에서 검증한 뒤 전환합니다. `pip install -U`로 전체 환경을 갱신하지 마세요. Python, CUDA wheel, 상위 소스 커밋, 모델 리비전, 의존성 잠금, 실제 청취 확인을 기록합니다.

가중치를 제자리에서 바꾸면 모델 식별이 달라져 기존 작업이 거부될 수 있습니다. 새 모델에는 새 작업을 만드세요. 장문 작품의 목소리·모델 설정은 고정되므로 전역 설정을 바꿔도 진행 중인 책에 적용하지 않습니다.

0.1~0.3은 schema 1을 사용하며 안정적인 UUID와 JSON 엔터티를 유지합니다. 0.2는 녹음·참조 비교·선택적 보관 필드를, 0.3은 `audio_processing`과 파생 녹음 출처를 추가합니다. 기존 작업은 미보관으로 취급하고 과거 오디오는 보존합니다. 0.4는 장문 테이블·열·색인, `lf_*`, 검토 이력, `asset_trash`를 증분 추가합니다. 이후 스키마 변경에도 백업과 명시적 마이그레이션이 필요하며 DB 삭제로 대신하지 않습니다.

## 보관과 휴지통

완료 작업은 기본 7일 뒤 보관합니다. `task_archive_after_days=0`으로 자동 보관을 끌 수 있습니다. 작업 큐에서 현재·보관 목록을 전환하고 단일·일괄 복구할 수 있습니다.

보관해도 오디오와 승인은 남으며 디스크 공간이 확보되지는 않습니다. 복구하면 기간을 다시 세고 보관된 작업의 재시도는 미보관 작업으로 생성합니다. 원래 UUID로 이전 결과와 이벤트를 조회할 수 있습니다.

휴지통도 파일을 보존합니다. 장문 장·구간을 삭제하거나 복구하면 통계를 다시 계산하고 영향받은 장은 재검토해야 합니다. 묶음 복구는 연결 관계를 유지하며 장 복구가 이전에 개별 삭제한 구간을 되살리지는 않습니다. 복구 불가능한 휴지통 비우기는 없습니다.

## 문제 해결

| 문제 | 확인할 내용 |
|---|---|
| 연결되지 않음 | 시작 파일이나 `voice start`를 실행하고 `runtime/logs/server.log`를 확인합니다. 포트 충돌은 설정에서 해결하고 작업 프로세스를 중복 실행하지 않습니다. |
| VRAM 부족 | 이 플랫폼의 작업을 멈추거나 모델을 해제하고 필요하면 다른 GPU 앱을 직접 닫습니다. 실패 작업을 보존하고 재시도합니다. |
| 속도·감정이 맞지 않음 | 근사적 제어입니다. 설명을 조정하거나 후보를 늘려 들어 보세요. |
| 장문 목소리가 변함 | 확인된 참조와 같은 모델·설정을 쓰고 구간 경계의 운율을 직접 확인합니다. |
| WAV 외 내보내기 실패 | FFmpeg와 인코더를 확인합니다. 원본 WAV는 남습니다. 채널 복제는 실제 스테레오 공간을 만들지 않습니다. |
| 자막·무음 자르기 충돌 | 둘 중 하나를 끕니다. 정렬 도구 없이는 단어 시각을 생성하지 않습니다. |
| 전역 명령을 찾지 못함 | 새 터미널을 열고 Codex MCP를 재시작·재연결합니다. 그동안 설치 폴더의 `bin\voice.cmd`를 사용하세요. |
| 일괄 작업 실패 | 각 작업의 error/events를 확인합니다. 성공 출력과 승인은 보존됩니다. |

## 검증 범위

코어 테스트는 테스트용 파형으로 계약을 확인합니다. 실제 모델, 브라우저 조작, 사람의 청취, 제작 승인은 별도로 검증합니다. 자동화는 음성을 승인하지 않습니다.

`scripts/verify_longform_scale.py`는 별도 포트 8962와 `runtime/longform-scale`을 사용하고 자신의 서비스만 종료합니다. 테스트 본문은 사용자의 작품 라이브러리에 넣지 않습니다. 검증 자료이며 정식 음성이나 사용자 콘텐츠가 아닙니다. 원본 크기, 분할, 자동 장, 블록 설정은 `longform`에 있습니다.

## 모델 및 인코딩 도구

모델 및 설정에서 준비 안 됨, 필요할 때 로드, 로드 완료를 구분합니다. 모델이 없으면 이유를 확인하고 설치 폴더에서 `install-voice.cmd`를 실행한 후 모델을 다시 확인하세요. 기존 음성을 다시 만들 필요는 없습니다. 필요한 경우 진단 로그를 펼쳐 볼 수 있습니다.

내보내기에서 FFmpeg 유무를 확인합니다. 없더라도 WAV를 원본 샘플레이트와 채널 수로 묶을 수 있습니다. 변환, 리샘플링, 음량 및 무음 처리에는 인코딩 도구가 필요합니다. 고급 내보내기의 원본 WAV 설정 사용은 후처리를 해제합니다.
