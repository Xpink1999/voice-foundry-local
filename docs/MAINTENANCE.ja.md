# 保守・復元・更新

## 日常の操作

インストール先で `start-voice.cmd`、`stop-voice.cmd`、`check-health.cmd` を使います。任意のグローバル CLI 登録後は `voice start`、`voice stop`、`voice health` も使用できます。起動用ファイルは WebUI も開きます。Windows サービスや自動起動タスクは登録しません。

モデルは生成時にのみ独立した推論プロセスへ読み込みます。標準では 30 秒間使われないとプロセスを終了し、重み、PyTorch ランタイム、CUDA コンテキストを解放します。待機時間は設定で変更できます。`voice unload` は停止中のサービスを起動せず、待機中の推論プロセスを解放します。ブラウザーを閉じると試聴は止まりますが、バックグラウンド処理は続きます。ツールを終了するには `stop-voice.cmd` または `voice stop` を実行し、サービスの終了を待ちます。保存済み音声は残り、長文の未完了部分は後で再開できます。起動とライブラリ閲覧ではモデルを読み込みません。軽量サービスのメモリは停止時に回収されます。

設定は `config/platform.json` です。保存先を変えるときは停止し、バックアップと素材・DB のコピーを行ってからパスを更新します。モデルだけ移動して旧パスを残さないでください。

ログは `runtime/logs/` にあります。`platform.log` はローテーションする例外ログ、`server.log` は起動と上流モデルの出力です。

## バックアップ

インストール先で実行します。

~~~powershell
bin\voice.cmd backup
~~~

SQLite のオンラインバックアップで整合した `platform.sqlite3` と `platform.json` を `data/backups/<UUID>` に保存します。**音声ファイルは含まれません。**

完全復元には、データディレクトリ全体も保存してください。`references`、`recordings`、`reference-comparisons`、`audio-processing`、`originals`、`exports`、`longform` を含みます。長文には原本・正規化本文、区間の生成試行、バックグラウンド書き出しがあります。モデルの `provenance.json`、ソースのコミット、依存関係のロックも保管します。大きな重みは固定リビジョンから再取得できます。

DB とファイルの時点をそろえるため、データ全体のコピー中はサービスを停止します。置換前には現状の復元用コピーを残してください。

グローバル登録前のユーザー PATH と Codex 設定は `data/backups/global-<日時>` にあります。私的な設定を含む可能性があるため、公開やログへの貼り付けを避けてください。

## 復元

1. サービスを停止し、現在のデータを別に保存します。
2. バックアップの SQLite、対応する設定、音声・本文フォルダーを設定先へ配置します。
3. モデル、参照、原本のハッシュを確認し、起動して状態とタスクを確認します。

中断した通常生成は失敗となり、旧結果を上書きせず再試行できます。長文の未完了区間は待機に戻り、作品は明示的な再開を待ちます。取り込み中断は原本から再解析し、書き出し中断は新しい書き出しを送信します。原本ハッシュの変更は再利用を拒否します。

一部の失敗を直すために、不明な partial ファイル、DB、音色ライブラリ全体を削除しないでください。

## 更新とスキーマ

先にバックアップします。新しいコードやモデルは隔離した環境・設定で検証してから切り替えます。`pip install -U` で環境全体を更新しないでください。Python、CUDA wheel、上流コミット、モデルのリビジョン、ロック、実際の試聴を記録します。

重みを直接置換するとモデルの識別が変わり、旧タスクが拒否される場合があります。新モデル用のタスクを作ってください。長文作品の音色・モデルは固定され、全体設定を変えても途中の本には適用しません。

0.1～0.3 は schema 1 で安定した UUID と JSON エンティティを保持します。0.2 は録音・参照比較・任意のアーカイブ項目、0.3 は `audio_processing` と派生録音の出典を追加します。旧タスクは未アーカイブ扱いで、過去の音声を保持します。0.4 は長文の表・列・索引、`lf_*`、審査履歴、`asset_trash` を追加します。今後の変更もバックアップと明示的な移行を行い、DB 削除で代用しません。

## アーカイブとごみ箱

終了タスクは標準で 7 日後にアーカイブします。`task_archive_after_days=0` で自動化を無効にできます。キュー画面で現在／アーカイブを切り替え、単件・一括復元できます。

音声と承認は残り、容量は空きません。復元すると期間を数え直し、アーカイブから再試行した新タスクは未アーカイブになります。元の UUID でも過去の結果とイベントを照会できます。

ごみ箱もファイルを残します。長文の章・区間の削除や復元で集計が変わり、影響した章は再審査が必要です。バッチ復元は関係を保持し、章を復元しても以前に個別削除した区間は戻しません。復元不能な一括消去はありません。

## よくある問題

| 問題 | 確認すること |
|---|---|
| 接続できない | 起動用ファイルか `voice start` を実行し、`runtime/logs/server.log` を確認します。ポート競合は設定で解決し、ワーカーを重複起動しません。 |
| VRAM 不足 | 本サービスのタスクを停止・アンロードし、必要なら他の GPU アプリを自分で閉じます。失敗タスクは残して再試行します。 |
| 速度や感情が合わない | 近似的な制御です。説明を調整するか候補を増やして試聴します。 |
| 長文で声が変わる | 確認済み参照、同じモデルと設定を使用し、区間のつなぎ目を試聴します。 |
| WAV 以外の出力に失敗 | FFmpeg とエンコーダーを確認します。元の WAV は残ります。チャンネル複製は本来のステレオ空間を作りません。 |
| 字幕と無音除去が競合 | どちらかを無効にします。アラインメントなしでは単語時刻を生成しません。 |
| グローバルコマンドが見えない | 新しいターミナルを開き、Codex MCP を再起動・再接続します。それまではインストール先の `bin\voice.cmd` を使用します。 |
| 一括処理で失敗 | タスクごとの error/events を確認します。成功音声と承認は保持します。 |

## 検証範囲

コアテストはテスト用波形で契約を確認します。実モデル、ブラウザー操作、人の試聴、制作上の受入は別に検証します。自動化が音声を承認することはありません。

`scripts/verify_longform_scale.py` はポート 8962 と `runtime/longform-scale` の独立サービスを使い、自分のサービスだけ停止します。テスト本文は利用者の作品庫に追加しません。検証資料であり、正式音声や利用者コンテンツではありません。原本容量、分割、自動章、ブロック設定は `longform` にあります。
