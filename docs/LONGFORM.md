# 长文配音与资产整理（0.4）

## 使用顺序

打开「长文配音」，导入整本 TXT / Markdown，选择人物和项目。导入后先检查目录及分段，再点击「继续生成全书」或选择某章点击「只生成本章」。关闭网页不停止后台；需要停止计算时点击「暂停生成」。重新启动平台后，打开原作品点击续作，已完成段不重做。

原文不必自带章节或换行：

- 识别独立的“第…章/节/回/卷/部/集/篇”、Chapter 数字/罗马数字、序章/楔子/尾声等以及 Markdown 标题。
- 没有标题时，按段落和约 3 万字符的边界组织“正文 / 正文·分章”。它们是自动管理单元，不声称是原书目录。
- 连段落都没有时，仍按标点和长度切成有界片段，并组织自动分章。默认每个语音段最多 160 字符；分段保留在规范化 UTF-8 文件中的字节位置和内容哈希。
- 这是规则识别，不是编辑审稿。目录、页眉或不常见标题可能需要复核；可在管理页排除错误章节/分段，再恢复或重新审核。

支持自动 / 手动 UTF-8、UTF-16（含有无 BOM 的明确字节序）、GB2312、GBK、GB18030。自动模式先识别 BOM，再对完整内容验证 UTF-8；不符合时尝试兼容 GBK/GB2312 的 GB18030。常见字符不足以唯一判断编码子集，因此自动导入的 GB2312 文件可能显示所使用的解码器“GB18030”。解码严格，不用替换字符掩盖乱码；失败保留原件，可重选编码重新解析。

## 规模与存储设计

长文不走普通 6 万字符输入框或 200 条批量接口，也不为整本书一次创建数十万个普通任务。SQLite 独立索引作品、章节、分段和尝试；网页只加载分页，全文留在磁盘。无换行长行也以有界块解析，分段索引每 1,000 条提交。

源文件接收和文本解析有独立状态；原始字节保存在 data/longform/<作品 UUID>/source.original。规范化文本另存 UTF-8，统一换行，不覆盖原件。原编码文件的 SHA-256 与规范化文件 SHA-256 都保留，分段偏移指向后者，不能直接当成原 GB2312/UTF-16 文件的字节偏移。

每个作品冻结人物版本、单个参考及转写版本、模型身份、参数、基础种子和分段/停顿配置。普通生成功能保持原有字数限制。长文文件默认限制 **2 GiB 原始文件字节**，这是可配置的接收保护，不是用一个超大字符字段喂给模型。实际可生产总量仍受磁盘、运行时间和模型能力约束。

## 生成、恢复与重试

长文与普通 TTS、音频修复共用模型与计算锁，每次生成一个小段并独立提交检查点。每段有状态、尝试次数、文字哈希、音频哈希、模型、参考配置哈希和实际种子。索引按作品/章节/状态查找下一段，成功段不会重新进入普通队列。

暂停或重启时，尚未完成的段回到待生成；成功段保持原文件和记录。某段失败会暂停提示，避免系统性错误污染余下整本书；可重试失败段，或先续作跳过失败段处理其他内容。模型或参考哈希变化会拒绝以不同条件续作。

“生成另一版本”使用新的种子变体，旧音频和尝试记录保留。只有成功段可以生成另一版本，失败段使用重试。切换人物/模型不是对既有作品的原地修改：需要用新的配置重新导入为另一作品，避免把数十万段混成不可追踪的多个声音配置。

使用固定参考可降低漂移，但不能保证长篇跨段韵律、人物声线绝对一致。单个模型调用是否能立即停止仍受其流式/返回边界限制；保存的成功段不受影响。

## 逐章试听审核

章节内可连续试听或单独试听某段，播放器一次只读取一个段；无需先把整章拼入浏览器内存。连续试听结束不会勾选确认或自动批准。

只有本章全部有效段成功，且用户明确确认已试听，才允许批准本章当前音频版本。重做、排除或恢复分段会使受影响章节回到待审核，其他章节的审核保持。审核历史留在 lf_reviews；旧版本音频留在独立尝试目录。

## 按章节 / 整本导出

在当前作品的「导出中心」选择当前章节、全书按章分文件或全书合成单文件。WAV、FLAC、MP3、OGG 沿用模型原始采样率，额外编码由本机 FFmpeg 完成。

正式导出要求所选有效章节全部完成并通过当前版本审核。未审核时必须显式勾选草稿，音频和压缩包带 DRAFT 标记，manifest 记录 draft=true。长文导出不会进入或篡改普通试听结果的批准状态。

后台按块写出音频和 ZIP64。预计 WAV 超过 RIFF 容量时使用 RF64；部分旧播放器可能不支持，可按章节拆分或选择 FLAC。整本合成保留中间章节 WAV，因而需要额外磁盘空间。没有在内存中拼接全书 PCM。

包内保留配置快照、来源哈希、segments.jsonl 原文及每段参数/音频哈希、chapters.jsonl、分段边界字幕。章节包还提供各章从零起算的 SRT；book.srt 使用整本时间轴。这是分段时间边界，不是词级强制对齐。

导出期间冻结本作品的生成变更，其他作品及普通 TTS 可使用服务。取消、失败、中断均保留已写文件；可重新提交新导出任务，不覆盖分段原件。下载通过流式文件响应，CLI 分块落盘并校验 ZIP SHA-256。

## 两种克隆

遵循[官方中文文档](https://github.com/OpenBMB/VoxCPM/blob/main/README_zh.md)：

- 可控声音克隆（API clone_mode=reference）：reference_wav_path 加可选的括号风格指令，语速/情绪/表现力为模型近似引导。
- 极致克隆（API clone_mode=hifi，兼容原有 Hi-Fi 名称）：同一片段同时传 reference_wav_path 与 prompt_wav_path，并提供对应的精确 prompt_text。沿用参考演绎，不叠加额外风格描述。

工作台可直接展开「核对本次参考的完整转写」并保存，不需寻找其他页面。这里填写的是参考录音的内容，不是要新生成的台词。普通工作台、批量配音和长文导入都有对应模式入口。自动转写未核对时保留草稿提示；不把“极致”作为绝对相似或人工听感通过的保证。

## 删除与审核导出的连贯操作

「管理与回收站」覆盖项目、人物、历史版本、参考片段/录音、任务、试听、导出、音频处理、参考对比，以及长文作品/章节/分段/导出。支持单条、批量、引用与关联预览、恢复所选及恢复同批。常用列表有删除或批量管理入口。

删除是**可恢复地移出日常列表**，不物理清空模型、原文、音频或冻结的追踪记录，也不等于释放磁盘。运行中的任务先停止；绑定人物的参考先解除绑定，或同批删除人物。当前人物版本不能单独删除。批量中任一对象被保护时整批不执行。

长文作品整体删除不展开百万级分段为独立删除项；章节删除用同一批次排除其有效分段。恢复章节只恢复该批次排除的段，不把更早已单独删除的段带回来。恢复改变内容时需要重新审核受影响章节。

普通「试听与审核」页可勾选结果、批量审核、直接选择格式并导出；确认框提供「批准并准备导出」。通过后不必切换到导出中心才能完成常规导出，高级参数仍可打开原导出中心。未确认试听不能批准，混有未审核结果不能正式导出。

## CLI / MCP / API

```powershell
voice import-book "D:\稿件\整本小说.txt" --encoding auto --voice-id <人物UUID>
voice book <作品UUID> --chapters
voice book-resume <作品UUID>
voice book-pause <作品UUID>
voice book-retry-failed <作品UUID>
voice book-segments <作品UUID> 1 --limit 25
voice book-export <作品UUID> --mode chapters --draft
voice book-export-status <导出UUID>
voice book-download <导出UUID> --dest "D:\输出"
voice assets --kind results
voice delete-assets --kind results --ids <结果UUID>         # 默认只预览
voice delete-assets --kind results --ids <结果UUID> --apply # 可恢复删除
voice restore-asset-batch <删除批次UUID>
```

长文 REST 前缀 /api/v1/longform，资产管理前缀 /api/v1/assets；在线 /docs 提供完整契约。MCP 新增长文导入、分页、续作、导出和资产管理工具，仍不提供代替用户试听批准的工具。新的 MCP 连接可发现 33 个工具；当前已连接的 Codex 需要重连，不必重复安装模型。

## 配置与维护

config/platform.json 的 longform 集中管理 max_source_bytes、segment_chars、fallback_chapter_chars、import_batch_segments、pause_ms、block_frames。只影响新作品的配置快照。数据库以增量表/列增加功能，不删除旧实体；正常在线备份包含长文索引和回收站元数据，完整恢复还必须备份整个 data/longform 以及原有录音/音频目录。

原始文件、规范化文本、每次生成和导出目录均保留。没有实现释放磁盘的不可恢复清理，也没有宣称完成千万字符全量语音的设备/听感验收。规模测试、真实生成和人工审核的区别见 [测试说明](TESTING.md)。
