# 参照整理と音声生成の流れ

## 録音から音声プロフィールを作る

1. 「音声を作成」で録音をアップロードし、利用権を確認します。原録音は個別に保持されます。
2. 話者追跡が利用できる場合は話者クリップの整理へ進みます。それ以外は元音声の候補を試聴するか、「話者と音声処理」から分析します。
3. 話者ごとに試聴し、保存するクリップを選びます。選択欄は一種類です。再生、ホバー、フォーカスで選択は変わりません。
4. クリップを個別に保存するか、同じ話者のクリップから複合参照を作成します。
5. 続けて新規音声を作るか、既存音声に追加します。新規作成時は既定の参照を選びます。既存の既定参照は変更しません。
6. 「この音声で生成」を選ぶと、その音声が選択された作業台で台詞を入力できます。

## 短いクリップから複合参照を作る

ユーザーが明示的に選んだ同じ話者のクリップだけを使います。人物の全発話を自動で結合しません。出典区間の重複、利用権、出力ごとの発話検出、時間を確認して下書きを作ります。既定は推定発話時間が5秒以上、間隔を含む全長が30秒以下です。`speaker_tracking` で設定できます。

ファイル長と推定発話時間は別の値です。無音や同じ出典の重複で最低時間を満たすことはできません。結合結果を試聴してから保存してください。最終音声を再度文字起こししますが、Hi-Fi利用前には校正が必要です。保存で自動承認されることはありません。

試聴用の結合は異なる話者でも利用できますが、単一話者の参照にはできません。順序、クリップ、間隔を変えると新しいファイルを作り、旧版を保持します。

## 話者の修正とトラック比較

「話者の割り当てと分析」で再割り当て、未割り当て、除外、取り消しを操作できます。名前と話者識別は別です。修正履歴を保持し、旧参照や音声スナップショットを書き換えません。派生素材には出典の変更を表示し、旧タイムラインは変更前の版として扱います。

単独発話と全体の話者タイムラインは別々です。全体トラックは各出典マップを使い、割り当て済みの重複発話も元の位置に戻します。未解決区間は原録音で確認します。無音だけで不在とは判断できません。発話時間は推定値で、声紋類似度は本人確率ではありません。

新規タスクは自動、1、2、3人に対応します。自動分析で3人を超えた場合は範囲外と表示し、無理に統合しません。任意の [SepFormer WSJ0-3Mix](https://huggingface.co/speechbrain/sepformer-wsj03mix) は8 kHzの3話者モデルです。リサンプリングで高域は復元せず、中国語の品質も未承認です。未導入なら重複区間は未解決として保持します。

```powershell
.\.venv\Scripts\python.exe scripts/setup_three_speakers.py
```

先に話者追跡環境を導入してください。モデルの修訂とハッシュを記録し、録音は送信しません。モデルを読み込めても、試聴による品質確認は別に必要です。

## 確認、修正、書き出し

通常の候補と長文セグメントは、再生成画面で今回の台詞と参照を変更できます。原文、原音声、旧版は保持されます。長文の変更は該当セグメントだけに適用し、その章の確認を無効にします。旧版を採用すると対応する制作テキストも戻ります。

各セグメントに問題を記録し、作品の問題一覧から章やページをまたいで移動できます。生成成功で手動の問題は消えません。解決済みにしても章は自動承認されません。通常候補の再生成タスクも元候補から再表示でき、重複生成しません。

確認画面は、確認後に書き出す順序で表示します。形式や削除はその他の操作にまとめています。通常の書き出しはバックグラウンドで続きます。再読み込み後も書き出し画面で元タスクの確認、取消、再試行、ダウンロードができます。未確認音声は下書きとして明示的に書き出します。

## 旧データと保守

更新前にサービスを停止し、データベースと設定をバックアップしてください。イベント連番表と問題表を追加しますが、既存素材は書き換えません。過去の結合は試聴用、旧タイムラインは単独発話のままです。未記録の測定値や確認状態は不明のままです。戻す場合は停止後、対応するデータベース・設定・ソースを一式で復元し、表だけを削除しないでください。

導入済みファイルと読み込み中のモデルは区別されます。ファイル不足では下書きを保持して導入方法を表示します。イベント再送は、推論を任意の音声位置から再開できる意味ではありません。

## ワークスペース間の操作

作業台から一括音声化・長文へ進むと、現在の台詞、プロジェクト、人物、参照、クローン方式、演技設定を引き継ぎます。「参照と生成設定」で参照、エンジン、言語、シードを確認できます。未送信の下書きがある場合は、置き換え前に確認します。作品には既定の人物を一人指定し、一括の配役を一人の声に変換しません。

一括の役名は、その行のプロジェクトで利用できる未アーカイブの人物だけに一致させます。一致しなければ人物を選び直せます。別の人物は各自の既定参照を使い、JSONの明示指定は保持します。送信後はその一括処理のタスクへ進み、候補の試聴へ移動できます。タスクと審査の範囲はURLから復元します。

プロジェクトやタスクから候補を開くと古い絞り込みを解除し、明示的な選択と非表示の選択数を保持します。書き出し履歴はプロジェクト、タイトル、ファイル名で検索でき、内容一覧から元の候補へ戻れます。削除済みの元データは利用不可と表示します。更新しても変更のない選択詳細は開いたままです。

モデル不足時は、一括送信、長文の再開、再生成の前に理由を表示します。既存音声の試聴と書き出しは利用できます。
